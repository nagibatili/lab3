# Bug Report — модуль MenuModule (проект FoodCampus)

## Общие сведения

| Параметр | Значение |
|---|---|
| Проект | FoodCampus (сквозной практический кейс) |
| Модуль | MenuModule, файл `menu.py` |
| Метод по интерфейсу архитектора | `get_filtered_menu(category, only_available)` |
| Окружение | Windows, PowerShell, Python 3.11.9 (вывод: `python --version`) |
| Версия 1 | Первая рабочая версия модуля (начальный вариант кода) — в ней негативное тестирование выявило дефекты |
| Версия 2 | Итоговая (исправленная) версия, файл `menu.py` в текущем проекте |

Дефекты выявлены при негативном тестировании версии 1 — скриптом `test_runner.py` и отдельными воспроизведениями. Все дефекты исправлены в версии 2, повторный прогон подтверждён (раздел 3).

## 1. Сводная таблица дефектов (формат из задания)

| ID | Модуль и метод | Входные данные | Ожидаемый результат | Фактический результат (версия 1) |
|---|---|---|---|---|
| BUG-01 | MenuModule.get_filtered_menu | Блюдо без поля `category` в списке: `{"name": "Компот", "price": 60.0, "available": True}` | Модуль не падает; блюдо с недостающим обязательным полем отклоняется при добавлении с понятным сообщением | Поле отсутствия проверки `add_dish` принимает блюдо, затем при любом запросе меню программа падает: `KeyError: 'category'` (высокая критичность) |
| BUG-02 | MenuModule.get_filtered_menu | Категория не-строкой: `123`, `None`, `""` | Сообщение об ошибке «category должен быть непустой строкой» (ValueError), программа продолжает работу | Ошибка скрыта: молча возвращается пустой список `[]`, ошибка повара-оператора не видна (средняя критичность) |
| BUG-03 | MenuModule.get_filtered_menu | Категория с другой буквой или пробелами: `"Суп"`, `"СУП"`, `"  суп  "` | Регистр/пробелы не влияют: как и `"суп"`, находятся 2 супа | Блюда «теряются»: возвращается `[]`, хотя в меню есть борщ и щи (средняя критичность) |
| BUG-04 | MenuModule.add_dish | Блюдо с отрицательной ценой: `{"name": "Каша", "category": "второе", "price": -50, "available": True}` | Отказ: «цена не может быть отрицательной» (ValueError), блюдо не попадает в меню | Блюдо принято и сохранено с `price: -50` (средняя критичность — испорченные данные) |

Фрагмент исходной версии 1, вызвавший дефекты (цитата из начального `menu.py`):

```python
def add_dish(self, dish):
    self.dishes.append(dish)          # нет никакой проверки блюда (BUG-01, BUG-04)

def get_filtered_menu(self, category, only_available=False):
    result = []
    for dish in self.dishes:
        if dish["category"] == category:   # нет проверки category (BUG-02),
                                           # сравнение чувствительно к регистру (BUG-03)
            if not only_available or dish["available"]:
                result.append(dish)
    return result
```

## 2. Детальное описание и воспроизведение дефектов

Все шаги выполнены из папки проекта; команда `python -X utf8 <файл>` гарантирует корректный вывод русского текста в Windows-консоли.

### BUG-01 — Падение программы: KeyError на блюде без обязательного поля

- **Компонент:** MenuModule.get_filtered_menu (виноват и add_dish, не проверяющий поля)
- **Критичность:** высокая (падает вся программа — любое обращение к меню)
- **Статус:** исправлено в версии 2, повторный прогон — пройдено

**Шаги воспроизведения** (скрипт-воспроизведение):

```python
from menu import MenuModule

m = MenuModule()
m.add_dish({"name": "Борщ", "category": "суп", "price": 120.0, "available": True})
print("До добавления сломанного блюда:", m.get_filtered_menu("суп", False))
m.add_dish({"name": "Компот", "price": 60.0, "available": True})  # нет поля category!
print("После добавления сломанного блюда:", m.get_filtered_menu("суп", False))
```

**Фактический результат (версия 1):**

```
До добавления сломанного блюда: [{'name': 'Борщ', 'category': 'суп', 'price': 120.0, 'available': True}]
Traceback (most recent call last):
  File "...probe01.py", line 8, in <module>
    print("После добавления сломанного блюда:", m.get_filtered_menu("суп", False))
  File "...menu.py", line 21, in get_filtered_menu
    if dish["category"] == category:
       ~~~~^^^^^^^^^^^^
KeyError: 'category'
```

Одна «сломанная» запись в списке блюд выводит из строя все запросы меню.

**Исправление:** в версии 2 `add_dish` проверяет наличие обязательных полей `name, category, price, available` и тип каждого поля; блюдо без поля отклоняется с понятным сообщением:

```
add_dish: блюдо отклонено: в блюде нет обязательных полей: category
get_filtered_menu по такому меню: []
```

### BUG-02 — Некорректная категория обрабатывается молча

- **Компонент:** MenuModule.get_filtered_menu
- **Критичность:** средняя (ошибка пользователя скрыта от него же)
- **Статус:** исправлено в версии 2, повторный прогон — пройдено

**Шаги воспроизведения:**

```python
from menu import MenuModule

m = MenuModule()
m.add_dish({"name": "Борщ", "category": "суп", "price": 120.0, "available": True})

print("category=123 :", m.get_filtered_menu(123, False))
print("category=None:", m.get_filtered_menu(None, False))
print("category='': ", m.get_filtered_menu("", False))
```

**Фактический результат (версия 1):**

```
category=123 : []
category=None: []
category='':  []
Программа завершилась без ошибок.
```

По User Story повар фильтрует меню по категории: если категорию передали с ошибкой, модуль обязан сообщить об этом, а не делать вид, что «блюд нет». Ожидаемое поведение — ValueError с пояснением.

**Исправление:** в версии 2 `get_filtered_menu` проверяет аргумент `category` (непустая строка) и `only_available` (булево). Теперь:

```
[OK] get_filtered_menu с числом вместо категории -> ValueError: category должен быть непустой строкой, например «суп», получено: число
[OK] get_filtered_menu с None вместо категории -> ValueError: category должен быть непустой строкой, например «суп», получено: None
[OK] get_filtered_menu с пустой строкой категории -> ValueError: category должен быть непустой строкой, например «суп», получено: строка
```

Важно: неизвестная, но корректная категория («напиток») по-прежнему возвращает `[]` — это нормальный ответ «ничего не найдено», а не ошибка.

### BUG-03 — Регистр и пробелы в категории: блюда «исчезают»

- **Компонент:** MenuModule.get_filtered_menu
- **Критичность:** средняя (повар не найдёт своё же блюдо)
- **Статус:** исправлено в версии 2, повторный прогон — пройдено

**Шаги воспроизведения:**

```python
from menu import MenuModule

m = MenuModule()
m.add_dish({"name": "Борщ", "category": "суп", "price": 120.0, "available": True})

print("category='суп':", m.get_filtered_menu("суп", False))
print("category='Суп':", m.get_filtered_menu("Суп", False))
print("category='СУП':", m.get_filtered_menu("СУП", False))
```

**Фактический результат (версия 1):**

```
category='суп': [{'name': 'Борщ', 'category': 'суп', 'price': 120.0, 'available': True}]
category='Суп': []
category='СУП': []
```

**Исправление:** в версии 2 категория нормализуется — не учитываются регистр и лишние пробелы (`strip().lower()` при сохранении и при поиске). Теперь:

```
Поиск «Суп» (большая буква): [{"Борщ" ...}, {"Щи" ...}]   # 2 супа найдены
Поиск «  суп  » (с пробелами): [{"Борщ" ...}, {"Щи" ...}]  # 2 супа найдены
```

### BUG-04 — Принимается блюдо с отрицательной ценой

- **Компонент:** MenuModule.add_dish
- **Критичность:** средняя (испорченные данные в меню)
- **Статус:** исправлено в версии 2, повторный прогон — пройдено

Так в задании: «Код должен быть чистым и обрабатывать ошибки (например, пустой список или отрицательные числа)».

**Шаги воспроизведения:**

```python
from menu import MenuModule

m = MenuModule()
m.add_dish({"name": "Каша", "category": "второе", "price": -50, "available": True})
print("Блюда в модуле:", m.dishes)
```

**Фактический результат (версия 1):**

```
Блюда в модуле: [{'name': 'Каша', 'category': 'второе', 'price': -50, 'available': True}]
Программа завершилась без ошибок.
```

**Исправление:** в версии 2 `add_dish` проверяет: цена — число (int/float, но не bool) и не меньше нуля:

```
[OK] add_dish с отрицательной ценой -> ValueError: поле price не может быть отрицательным
```

## 3. Повторное тестирование после исправлений

Прогон демо-драйвера на версии 2 (`python -X utf8 test_runner.py`):

- 4 позитивных сценария — пройдены (assert-проверки);
- поиск «Суп», «СУП», «  суп  » — находят 2 супа;
- 12 негативных сценариев — каждый завершается понятным `ValueError` вместо молчания или падения (все помечены `[OK]`);
- сценарий BUG-01: блюдо без поля отклоняется при добавлении, `get_filtered_menu` не падает;
- граница: цена 0 (бесплатное блюдо) — принимается корректно;
- код возврата: 0.

Прогон модульных тестов (`python -m unittest test_menu.py -v`):

- `Ran 42 tests in 0.002s` — `OK`, код возврата 0;
- 21 из 42 тестов — проверки на некорректные данные (по каждому дефекту написаны закрепляющие тесты).

## 4. Как проверить воспроизведение дефектов версии 1 (по желанию преподавателя)

Фрагмент версии 1 из раздела 1 достаточно вставить в файл `menu.py` (заменив текущий класс) и запустить `python -X utf8 test_runner.py` — негативные сценарии снова покажут `[FAIL]` и падение `KeyError`. Итоговый набор тестов при этом покажет «не OK», что и подтверждает ценность исправлений.
